第 0 章　全员共同课

0.1 这条链路在做什么

发射端 standard/example_tx.py 把一个文件变成一段 48 kHz 的实信号 WAV。接收端 n2 把这段 WAV 变回原来的字节。空中接口以发射端为准：子载波位置、训练序列、QPSK 比特顺序、扰码、LDPC、帧头字段必须和发射端逐比特一致。同步、信道和译码调度可以换算法，换完之后仍要解开发射端生成的 WAV。

WAV
找前后 Chirp，用前 8 个训练符号锁住 OFDM 体起点　B
若干定时 / 钟偏候选上只解第 1 个数据符号，PH 头 CRC 通过者入选　BA
用前后训练把载荷钟偏收到 1 ppm　B
按该钟偏取出有效子载波，前后训练估计 H，沿符号插值　C
均衡、去公共相位、软 QPSK、解扰、LDPC　C
按帧头文件名和 file_size 写出文件　CA

编排函数是 recover_array。立体声在 recover_from_channels 里按能量从大到小逐路调用它，一路成功就停。

频点与 bin 的关系：f = k × 48000 / 8192。bin 400 约 2344 Hz，bin 2391 约 14010 Hz。声学通带大致在 2–14 kHz。

一个数据符号的比特账：

  • 1992 个 QPSK × 2 bit = 3984 bit = 498 字节，这是一个 LDPC 码字。
  • 码率 1/2，信息部分 1992 bit = 249 字节。
  • 发射端先把「249 字节帧头 + 文件字节」补零到 498 的整数倍，再按 249 字节切块，每块编成一个 OFDM 符号。

因此数据符号数 K 是偶数。receiver.coded_symbol_count 写成：

return 2 * ((info_block + file_size + coded_bytes - 1) // coded_bytes)

n2/receiver.py:45-47

0.4 用 r1 把符号数算一遍

metrics.json 里：file_size=9829，declared_symbols=40，K=42，blocks_ok=41/41。

  1. 帧头字段 declared_symbols 来自发射端 ceil(2×file_size/498)。2×9829/498 ≈ 39.47，向上取整得 40。它只按文件长度估算，不含 249 字节帧头。
  2. 未编码字节 = 249 + 9829 = 10078。补到 498 的整数倍：ceil(10078/498)=21 段，每段 498 字节，再拆成 2 个 249 字节信息块，共 42 个码字。这就是 K。
  3. 第 1 个数据符号在搜头时已经译过。载荷循环从第 2 个数据符号开始，所以 LDPC 统计是 41 个码字。
陷阱　declared_symbols 用来核对帧头是否自洽，循环上界用 K。三个人都要能在纸上重算这三步。

第 1 章　成员 A：空中接口A

成员 A 的交付物是一张「一个字节如何变成子载波，又如何变回来」的对照表。成员 B、C 的所有数组形状都以这张表为准。

阅读顺序：params.py → phy.py → standard/example_tx.py 的 mapp、train_symbol_gen、sequence、header_gen、file_process、ldpc_encoding → LDPC/new_ldpc/README.md 前 80 行。

1.1 参数从哪来

TX_DEFAULTS 与发射端构造函数的默认值对齐。derived() 只做推导，不改物理定义。训练种子 TRAIN_SEED=80，扰码种子 SCRAMBLER_SEED=0x5A4D，帧头魔术字 b'PH'。

必须　训练序列用 Python 标准库 random.seed 和 random.randint。NumPy 的随机数序列和它不同，换了之后训练符号对不上，后面的相关峰和信道估计都会错。

1.2 线性扫频

phy.linear_chirp 复现发射端相位，幅度系数 amp=0.8。整段 OFDM 体在发射端还会按峰值归一化；扫频本身用这个幅度。成员 B 用这条本地扫频做匹配滤波，所以相位公式差一个符号，峰就会消失。

1.3 QPSK：字节到位、位到子载波

发射端 mapp 对每个 498 字节块、每个子载波下标 i = 0 .. 1991：

  • d_i = i // 4：这个符号来自块内第几个字节。
  • b_i = 3 - (i % 4)：字节内从高位对走到低位对。i%4=0 时 b_i=3，取的是 bit7 和 bit6。
  • I = 1 - 2×bit_I，Q = 1 - 2×bit_Q。bit 为 0 时该路是 +1，bit 为 1 时是 −1。
  • 每对里 低位走 I、高位走 Q。对 b_i=3，bit6 走 I，bit7 走 Q。
  • X[400+i] = I + jQ，X[8192-400-i] = conj(X[400+i])。负频率是正频率的共轭，IFFT 取实部后才是实信号。
  • 时域：IFFT 的实部，再把最后 2048 点复制到前面，这就是循环前缀。

phy.bytes_to_qpsk_grid 与这段一一对应。接收端软解调在主路径里用 qpsk_llr_scaled：每个子载波先输出 Q 的 LLR，再输出 I 的 LLR，于是字节内仍是 bit7、bit6、bit5……bit0。

LLR 的定义是 log P(bit=0)/P(bit=1)，正值更像 0，和 I=1-2×bit 的符号一致：实部为正时 I 比特更像 0。硬判决可用 slice_qpsk：实部、虚部各自取符号。

1.4 训练符号

train_symbol_gen(..., symbol_count=16) 一次生成 16 个。前 8 个放在数据前，后 8 个放在数据后。每个数据 bin：

rand_num ∈ {0,1,2,3}
I = 1 - 2*(rand_num & 1)
Q = 1 - 2*((rand_num >> 1) & 1)

和数据 QPSK 同一张星座。phy.train_freq_time 返回频域 (16, 8192) 和带循环前缀的时域 (16, 10240)。成员 B 做相关时用时域；成员 C 做信道估计时用频域的有效 bin。

1.5 扰码

15 位线性反馈移位寄存器，种子 0x5A4D。每位输出是 bit14，反馈是 bit14 异或 bit13，然后左移，新的最低位放反馈。每个码字单独从种子重新开始。

发射顺序：LDPC 编码之后，码字比特与这条序列异或，再打包成字节。字节内 MSB 先入：scrambled[8j] 是该字节的 bit7。

接收端在 LLR 上解扰，见 descramble_llr：扰码比特为 1 时把该 LLR 乘 −1。等效于「比特异或 1 会交换 0 和 1 的似然」。先硬判再异或也可以在无噪声时得到同样比特，但会丢掉软信息，LDPC 需要的是软信息。

1.6 LDPC 调用约定

使用仓库内 LDPC/new_ldpc，Jossy 2018 的 IEEE 802.16 原型图实现。

ldpc.code(standard="802.16", rate="1/2", z=166)
app, it = coder.decode(llr, dectype="sumprod2")

N=24z=3984 bit 码字，K=12z=1992 bit 信息。该实现把原型图移位取 proto % z，与发射端必须是同一个库。app < 0 判为 1。decode_path.LdpcBank.decode_codeword 先解扰，再译码，返回信息比特、整码字比特和迭代次数。迭代次数小于 200 视为收敛。

环境　Windows 上需要把 LDPC/new_ldpc/src/c_ldpc.c 编译成 bin/c_ldpc.dll，否则 LdpcBank 初始化失败，主路径在译码前就返回阶段 ldpc。

1.7 PH 帧头

249 字节信息块的布局（header_gen）：

字节内容
0:2b'PH'
2版本 0x00
3:7file_size，4 字节大端
7:11declared_symbols，4 字节大端
11:UTF-8 文件名
文件名后 1 字节0x00，因为 bytearray 初值是 0，这里没有另写字符
再 4 字节CRC32，大端
其余0

CRC 覆盖 ba[:11+len(filename)]，含魔术字到文件名最后一字节，不含结束 0x00，不含 CRC 自身。parse_ph_header 用 zlib.crc32 重算，不一致就返回 None。文件内容里也可能出现字节 PH，所以 CRC 通过才算找到头。

_try_header 还要求：declared_symbols == (file_size+248)//249，并且文件名非空。(file_size+248)//249 就是 ceil(file_size/249)，与 ceil(2×file_size/498) 相同。r1 上两边都是 40。

载荷切取在 extract_payload：从 offset+249 开始，长度 file_size。主路径把头放在信息流开头，offset=0，所以是字节 [249 : 249+file_size]。末尾补零码字留在信息流里，写出文件时按 file_size 截断。

第 2 章　成员 B：捕获与对准B

成员 B 的交付物是一张 r1 的时间轴：两个 Chirp 峰、OFDM 体粗起点、第一训练起点、后训练起点、K、钟偏 ppm。成员 C 拿到的是「起点 + 钟偏」已经选好之后的频谱。

阅读顺序：capture.py 的 find_two_chirps、parabolic_peak、coarse_body_start → align.py 的 matched_start、find_end_preamble、extract_active_sfo、training_peaks、best_sfo_near → receiver.py 的 _lock_frame、_trust_sfo、_header_jobs、_payload_sfo_search。

dechirp_sfo、resample_clock、cfo_search、extract_ffts 是同一目录里的工具。主路径取符号走 extract_active_sfo，整段重采样标志在 r1 上是 resampled=false，cfo_hz=0。

2.1 匹配滤波在找什么

把本地模板时间反转，再与接收波形做卷积，等价于相关。fftconvolve(..., mode="valid") 的输出再平方，峰值位置就是模板起点。

Chirp 模板长 144000 点，训练模板是前 2 个训练符号接起来，长 2×10240。平方之后的峰用三点抛物线插值，得到亚采样位置。parabolic_peak 在整数峰 i 及其左右两点上拟合抛物线，修正量限制在 ±1 个样点内。r1 的第一训练起点因此可以是 212925.047，而不是整数 212925。

2.2 锁帧

_lock_frame 做这几件事：

  1. find_two_chirps：全段 Chirp 相关，取两个最强峰，按时间排序。第一峰信噪比要大于 8 才算 ok。r1 的两个峰信噪比都在 105 量级，peak1≈44926，peak2≈830837。
  2. coarse_body_start：第一峰 + 144000 + 24000。这是 OFDM 体的粗起点，误差可以到几百个样点，下一步再收紧。
  3. matched_start：在粗起点前后各约 2.5 个符号的窗里，用前两个训练符号做相关。返回的 snr 要 ≥ 4。r1 的 lock.snr≈7271。
  4. find_end_preamble：从第一训练起点往后，用后 8 个训练符号做相关。峰相对起点的样点数除以 10240，得到 n_sym_raw。K = round(n_sym_raw) - 8。r1 上 n_sym_raw≈49.9994，K=42。K 还必须落在 1 到 20000。

后训练模板是 8 个符号，相关峰出现在这 8 个符号的起点，所以偏移量是「前 8 训练 + K 个数据」，再减 8 得到 K。

2.3 采样钟偏

录音设备的采样率与 48000 Hz 有微小相对偏差，记为 sfo，单位是相对比例。ppm 是 sfo×10⁶。r1 约 −11.65 ppm，即 sfo≈-1.165×10⁻⁵。

这个偏差会随时间积累。一个符号 10240 点，42+16=58 个符号的 OFDM 体大约 59 万点，11.65 ppm 大约累积 7 个样点。只锁住开头、后面仍按 10240 等间隔切，尾部训练会慢慢滑出 FFT 窗。

主路径把钟偏留在取样网格里。extract_active_sfo 对第 m 个符号、FFT 内第 n 点，取样位置是：

start + (1 + sfo) * (m*10240 + 2048 + n)

+2048 先跳过循环前缀。然后对原始 WAV 做线性插值，再对这 8192 点做 rFFT，只保留 bin 400 到 2391。越界就抛出 ValueError，调用方把它当成这次候选失败。

钟偏从两个几何量来：

  • 后训练：sfo_end = end_offset / ((8+K)×10240) − 1。
  • 双 Chirp：sfo_chirp = (peak2−peak1) / 标称间距 − 1。标称间距是一条扫频 + 两段静音 + 全部 OFDM 符号。

_trust_sfo 的选择规则：

  • 后训练的 n_sym_raw 与整数之差小于 0.08，且 |sfo_end|<5×10⁻³ 时，采用训练估计。
  • 此时若 Chirp 估计也可靠，且两者相差小于 80 ppm，才取平均。
  • 训练间距还没对齐时，才改用 Chirp 估计。
  • 两者都不可靠时用 0。
陷阱　两个差很远的估计取平均，会得到几十万 ppm 的无效钟偏。两个数的中位数等于平均值，所以这里不能用 median。r1 的 n_sym_raw 离 50 只有约 0.0006，走训练估计这条。

2.4 用帧头 CRC 选候选

几何锁给出一个起点和一个钟偏中心，仍可能偏几个到几百个样点。_header_jobs 在锁点附近构造候选：

  • 起点偏移：0、±128、±256、±64 样点。
  • 钟偏：中心，以及中心 ±5、±10、±20、±30 ppm。
  • 中心的绝对值大于 40 ppm 时，额外把 0 ppm 放进中心列表。

每个候选调用 _try_header：用该起点和钟偏取出 9 个符号（8 训练 + 第 1 个数据符号），估计 H，解第一个数据符号。parse_ph_header 返回非空才保留。多个候选都通过时，用前 8 个训练的信道能量当分数，留能量更大的；实现里一旦找到一个通过的头就会 break，所以先加入列表的锁点候选优先。

锁点全部失败时，才调用 training_peaks：在整段 WAV 上找前两个训练符号的相关峰，最多 4 个，相邻峰至少隔半个符号。每个峰再用 best_sfo_near 在 ±200 ppm、步长 25 ppm 上选训练残差最小的钟偏。这条路径用于 Chirp 对不可用、但训练相关仍在的录音。

2.5 载荷钟偏再收细

头已经通过之后，_payload_sfo_search 在入选钟偏的 ±50 ppm 内按 1 ppm 步进。每个假设上分别取出前 8 个和后 8 个训练，拼成 16 行，做一次最小二乘，用中位训练残差当代价，取得分最低的 payload_sfo。后面所有数据符号都用这个钟偏调用 extract_active_sfo。

r1 的 clock_error_ppm 是搜头阶段的钟偏；payload_ppm 若写在诊断里，是这一步细化后的值。

2.6 分数定时在频域里意味着什么

主路径用插值直接取到「去掉 CP 之后的 8192 点」，分数样点体现在 start 的小数部分和 sfo 里。

sto_phase 和 extract_ffts 是另一套取符号方式：整数点截取，再用 exp(-j 2π k Δ / N) 补偿分数延迟。Δ>0 表示 FFT 窗比信号晚了 Δ 个样点。当前 recover_array 走插值网格，这两支函数留给对照和实验。

2.7 成员 B 的讲解提纲

在 r1 的时间轴上标出：

  1. peak1、peak1+144000+24000、sync_start 三者相差多少样点。粗起点和最终锁点应该只差搜索窗里的一个小修正。
  2. end_offset / 10240 ≈ 50，减 8 得 K。

第 3 章　成员 C：信道、均衡与译码C

成员 C 的交付物是：给定成员 B 的起点和钟偏，说明一个数据符号怎样变成 249 字节，以及 r1 的 41 个码字为什么全部收敛。

阅读顺序：channel.h_and_llr_scale、lerp_h → receiver.py 的 _try_header、_equalize_once、_decode_payload_symbol、recover_array 后半段 → decode_path.LdpcBank、extract_payload → report.py 怎样把这些写进 metrics.json。

wiener_smooth、cpe_and_nlms、hermitian_gate、turbo_refine、decode_frame 是同一文件里的备用算法。recover_array 把 turbo 写成 False，均衡用的是下面这条更短的路径。

3.1 最小二乘信道

训练符号的频域已知，记为 X，接收为 Y。每个有效 bin：

H = mean(Y / X)

h_and_llr_scale 对多行训练做这个平均，再算每音残差 |Y−HX|² / |H|²。有效音是 |H| 大于最大幅度 10−8 倍的那些 bin。噪声方差取有效音残差的中位数，并且不小于 10⁻³。

LLR 尺度：

reliability = noise_var / 每音残差
scale = 3 * clip(sqrt(reliability), 0.25, 4)

残差小的子载波尺度接近上限，深衰落或很吵的子载波尺度被压到 0.25 附近。这个尺度只乘在 LLR 的幅度上，不翻符号。

r1 的 mean_abs_h≈2.34。训练 QPSK 的幅度是 √2≈1.41，所以平均 |Y| 大约是 |H|×√2。具体增益还包含发射归一化和录音音量，成员 C 要会读这个量，用它比较不同录音，而不是把它当成一个固定常数。

3.2 头符号怎样被解出来

_try_header 取出 9 个符号的有效子载波。前 8 行估计 H 和 scale。第 9 行是第一个数据符号：

Z[k] = Y[k] / H[k]     # 仅 valid 的 bin

然后 qpsk_llr_scaled → 解扰 → LDPC。信息比特打成 249 字节，送入 parse_ph_header。通过之后，这个 249 字节原样保留为 header_raw，后面和载荷信息字节拼在一起。

这里的 H 只用于挑选候选。载荷会重新估计信道。

3.3 载荷上的四套 H

_payload_sfo_search 已经用前后训练一起做过一次联合估计，得到 h 和 scale。整段体取出之后再分两套：

  • h_front：前 8 个训练。
  • h_tail：后 8 个训练。尾部越界时，尾部退化为联合估计。

对第 i 个载荷符号（从 0 起，对应数据符号 1，因为数据符号 0 是帧头）：

alpha = (i+1) / max(K-1, 1)
H(alpha) = (1-alpha) * H_front + alpha * H_tail

r1 的 K=42，第一个载荷符号 α=1/41，最后一个 α=1。信道沿符号从前往后线性过渡，用来跟上录音过程中缓慢变化的声学信道。

_equalize_once 在选定的 H 上：

  1. Z = Y/H。
  2. 硬切片得到 X̂ = sign(Re Z) + j sign(Im Z)。
  3. 用 |H|² 加权，估计公共相位 θ = angle(Σ |H|² Z conj(X̂))。
  4. Z ← Z × exp(-jθ)。这一步把整符号转回实轴附近，正频率一起转。
  5. 用同一套 scale 出 LLR 并译码。

某个码字的迭代次数小于 200 就接受。否则按顺序改试联合 H、仅前训练、仅后训练，以「迭代次数更小，其次是中位 |LLR| 更大」为优。

3.4 从 LLR 到文件字节

一个符号的 Z 长度 1992。qpsk_llr_scaled 得到 3984 个 LLR，并裁剪到 ±30。LdpcBank.decode_codeword 解扰后译码，取出前 1992 个信息比特。bits_to_bytes 按大端打包成 249 字节。

41 个载荷符号接成 payload_bytes。信息流是 header_raw + payload_bytes。extract_payload 丢掉前 249 字节，再取 file_size 字节。r1 得到 9829 字节的 cute.jpg。

全部迭代次数都小于 200 时，payload_complete=true，recover_array 返回 ok=True、阶段 ok。有文件但有码字未收敛时，阶段是 ldpc，诊断里写明已按帧头长度写出。CRC 已通过但载荷不完整时，输出文件名带 .partial 这一类标记；以 write_run_outputs 的实际分支为准，读一份失败录音的 recovered_name 即可确认。

file_match：若 source/ 中有与帧头同名的文件，逐字节比较。r1 对应 source/cute.jpg，结果为 true。
